# 数字人智能体平台

第一版以搭好框架并跑通网页端数字人会话为目标：从卡片选择数字人，在双栏抽屉中查看历史会话、发送文字或文档、连续追问，并实时查看回复与执行过程。

架构与目录职责见 [第一版架构基线](docs/architecture-v1.md)。该文档定义实现范围、模块依赖、执行流程、数据归属、接口协议和验收条件。

已实现数字人卡片、按数字人隔离的会话列表、会话详情、纯文字与文档消息、连续追问、实时事件、刷新恢复与停止回复。数字人、模型和技能仍通过配置文件管理；MCP 服务可在网页管理连接、工具与数字人绑定。界面使用 Ant Design Vue 4.2.6 与官方图标组件，主题统一配置在 `apps/web/src/ui/theme.ts`。真实模型优先使用 DeepSeek / OpenAI 兼容 Chat Completions，另保留 OpenAI Responses 适配。

## 本地运行

需要 Node.js 22.12 或更高版本以及 pnpm 12。首次运行先执行 `pnpm install`。

无需模型凭证的本地演示：

```sh
pnpm dev:demo
```

打开 [数字人工作台](http://127.0.0.1:5173/)，点击数字人卡片，在抽屉中选择或新建会话。可以直接输入文字，也可以上传 `.md` / `.txt` 或点击“使用示例”。演示使用固定模板，不调用模型，界面和输出均有标记。

真实模型执行：复制 `.env.example` 为 `.env`，填写 `DEEPSEEK_API_KEY`，确认 `DEEPSEEK_MODEL` 和 `DEEPSEEK_BASE_URL`，然后执行：

```sh
pnpm dev
```

没有凭证时仍可打开网页，数字人会显示未配置原因并阻止提交。不要将密钥放入浏览器或数字人指令。

构建并以单服务提供网页和接口：

```sh
pnpm build
pnpm start
```

打开 [本地交付服务](http://127.0.0.1:3100/)。服务仅监听本机；首版不包含账号和多租户能力。构建生成 Web 静态文件，后端通过 tsx 运行 TypeScript 源码，当前不是可独立发布的 npm 软件包。

## 开发与验证

```sh
pnpm typecheck
pnpm test
pnpm exec playwright install chromium
pnpm test:e2e
```

测试覆盖真实 SDK 对本地兼容接口的多轮历史、多步工具调用、用量与轮次限制，以及会话归属、任务幂等、工具权限、取消、超时、重启恢复、SSE 补读和旧数据库迁移。供应商未返回用量时保存 null，不用零值代替未知值。真实供应商验收与演示测试分别记录。

当前通过类型检查、生产构建、43 项集成测试和 7 项浏览器验收。真实 DeepSeek 已验证 MCP 示例资料查询、文档分析，以及无附件文字会话中连续两轮的上下文记忆；旧版 3 个会话及其任务、上传和消息均已迁移保留。

网页验收会构建并启动独立的本机 3101 端口服务，数据保存在 `data/e2e`，结束后自动关闭；不复用日常开发服务。Markdown 结果只允许文本排版标签，不自动加载远程图片或执行脚本。

## 会话与历史

左侧会话列表只加载当前数字人的会话，右侧展示所选会话内的全部消息；较长会话可加载更早消息。刷新或分享当前网址会恢复数字人与会话选择，旧的 `/tasks/:id` 链接会打开对应会话。

每次发送产生独立的 Task 和 Run，同一 Session 可以包含多轮。模型接收最近最多 20 条已完成的用户与助手消息，上下文总量限制为 32,000 字符；不回放上次运行中的工具状态。追问默认复用本会话最近的文档，重新上传后使用新文档；不同会话之间不能复用文件标识。

数据库启动时自动执行按序编号且经过 hash 校验的迁移。0002 迁移保留原会话、任务、上传与运行记录，并允许纯文字消息。

## 模块目录

| 目录 | 职责 |
| --- | --- |
| `apps/web` | Vue 3 + Ant Design Vue 网页操作入口 |
| `apps/server` | Fastify 接口、SSE、应用装配与生命周期 |
| `packages/contracts` | 前后端共享的数据结构与校验 Schema |
| `packages/core` | 业务实体、应用用例、权限决策与外部依赖接口 |
| `packages/agent-runtime` | OpenAI Agents SDK 适配与执行事件转换 |
| `packages/infrastructure` | 配置、SQLite、文件、技能资源、工具执行与日志适配 |
| `config` | 平台、模型与 MCP 初始配置 |
| `resources` | 数字人预设与技能资源 |
| `mcp-servers/reference` | 独立 MCP 示例服务与公开资料 |
| `tests` | 集成与网页闭环验收 |

运行时产生的 `data/` 与 `workspaces/` 不属于源码。API 密钥由服务端环境变量提供。

## 自定义能力

新增技能见 [扩展说明](docs/extensions.md)。首版启动时扫描技能，修改配置或资源后重启生效，已开始的运行使用固定快照。

MCP 已支持 Stdio 与 Streamable HTTP 的只读工具接入。打开“MCP 管理”可新增、测试、编辑、启停或删除服务，选择只读工具并绑定数字人；保存后立即作用于新任务，已有任务保留原快照。`config/mcp.yaml` 仅在本机首次启动时导入，后续配置保存在 `data/mcp-settings.json`（使用自定义数据目录时随之调整）；网页填写的 Bearer 凭证只写不回显，文件权限为 0600。默认需求分析师绑定独立的 reference 资料服务：新建会话点击“查询 MCP 示例资料”并发送，即可查看实际 MCP 调用和资料来源。接入自定义服务见 [扩展说明](docs/extensions.md)。
