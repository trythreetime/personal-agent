# 小团队任务看板需求说明

版本：V1.0 初稿  
文档用途：首版产品需求分析与任务拆分  
产品形态：网页应用

## 一 背景与目标

一个小型项目团队目前通过聊天消息和电子表格记录工作事项。任务分散在不同地方，经常出现负责人不明确、进度更新遗漏、截止时间难以追踪的问题。

希望开发一个轻量的网页任务看板，让团队负责人集中登记任务、维护状态，并快速查看当前工作进度。

第一版由团队负责人统一操作，验证任务管理流程是否有效。成员姓名仅作为负责人标签，不代表登录账号；暂不提供多人同时编辑、账号注册或权限管理。

产品需要实现以下目标：

- 在一个页面内查看待处理、进行中和已完成的任务。
- 每个任务都有清晰的标题、状态与负责人信息。
- 可以快速找到某位成员负责的任务，以及已经逾期的任务。
- 任务保存后，刷新页面或重启服务仍然能够查到。

## 二 首版范围

第一版包含任务创建、列表与看板展示、任务详情、任务编辑、状态变更、搜索筛选、进度统计和任务删除。

第一版不包含账号体系、角色权限、多人协作、子任务、任务依赖、附件上传、评论、消息通知、日历同步或移动端原生应用。

先支持一个工作空间，不区分多个项目。数据导出和操作历史是否纳入后续版本，另行确认。

## 三 主要使用场景

### 登记任务

团队负责人收到一项工作后，点击“新建任务”，填写标题、描述、负责人、优先级和截止日期。保存成功后，新任务出现在“待处理”区域。

### 更新进度

负责人在每日检查时，将已经开始的任务改为“进行中”，将已经交付的任务改为“已完成”。如果已完成的工作需要返工，可以重新改回“待处理”或“进行中”。

### 检查成员工作

负责人选择某位成员，查看分配给该成员的任务，再结合任务状态判断当前进度。取消筛选后恢复查看全部任务。

### 检查逾期事项

负责人启用“仅看逾期”，找到截止日期已过但尚未完成的任务，查看详情并调整安排。

## 四 任务数据

| 字段 | 是否必填 | 规则 |
| --- | --- | --- |
| 任务编号 | 系统生成 | 创建后保持不变，唯一标识一条任务 |
| 标题 | 是 | 去掉首尾空格后为 1 至 100 个字符，不接受纯空白内容 |
| 描述 | 否 | 最多 5,000 个字符，支持多行纯文本 |
| 负责人 | 否 | 从预设成员中选择；未选择时显示“未分配” |
| 状态 | 是 | 待处理、进行中、已完成；默认待处理 |
| 优先级 | 是 | 高、中、低；默认中 |
| 截止日期 | 否 | 精确到日期，允许为空或填写过去日期 |
| 创建时间 | 系统生成 | 任务第一次保存成功的时间 |
| 更新时间 | 系统生成 | 最近一次成功修改任务的时间 |

第一版预设三位成员：成员甲、成员乙、成员丙。暂不提供成员管理页面，也不需要保存手机号、邮箱等个人信息。

## 五 功能要求

### 任务创建

- 提供新建任务表单，明确标记必填项。
- 输入不符合规则时，在对应字段附近显示原因，并保留已填写内容。
- 保存期间给出反馈，避免重复点击造成重复任务。
- 保存成功后关闭表单，更新当前任务列表和统计信息。
- 保存失败时提示失败，保留表单内容，允许用户重试。

### 任务展示

- 提供列表视图和看板视图，用户可以切换。
- 看板按待处理、进行中、已完成分为三列。
- 任务卡片至少显示标题、负责人、优先级和截止日期。
- 有截止日期且已经逾期的未完成任务，需要有明确的逾期标记。
- 列表和各看板列内按更新时间从新到旧排列；更新时间相同时，排序应保持稳定。
- 没有任务或筛选后没有结果时，展示明确的空状态。
- 首版通过按钮或状态选择器修改状态，不要求拖拽卡片。

### 任务详情与编辑

- 点击任务可以查看全部字段。
- 可以修改标题、描述、负责人、状态、优先级和截止日期。
- 编辑取消时不保存修改。
- 保存成功后同步更新列表、看板和统计信息。
- 不要求每次修改都记录完整的操作历史。

### 状态变更

- 三种状态之间可以相互切换，不强制按照固定顺序流转。
- 状态变更成功后，任务立即出现在对应的看板列中。
- 更新失败时提示错误，界面应恢复为最后一次成功保存的状态。

### 搜索与筛选

- 支持按标题关键词搜索，英文搜索不区分大小写。
- 支持按负责人、状态和优先级筛选。
- 支持“仅看逾期”，可以与其他条件组合使用。
- 多个筛选条件之间采用“同时满足”的关系。
- 提供“清空筛选”，一次恢复查看全部任务。
- 筛选条件只影响任务展示，不修改任务数据。

### 进度统计

页面顶部显示任务总数、待处理数、进行中数、已完成数和逾期数。

统计始终基于整个工作空间的全部未删除任务，不随当前搜索和筛选条件变化。逾期任务同时计入其所属状态，不作为第四种任务状态。

### 任务删除

- 在任务详情中提供删除入口。
- 删除前显示任务标题，并要求用户确认。
- 取消确认后保留原任务。
- 删除成功后，从列表、看板和统计中移除。
- 第一版不提供回收站；界面需要明确说明删除后无法通过产品恢复。

## 六 业务规则与异常处理

1. 逾期的定义是：截止日期早于当天，且任务状态不是“已完成”。截止日当天不视为逾期。
2. 日期判断统一以 Asia/Shanghai 时区为准。
3. 已完成任务即使截止日期已过，也不显示为逾期。重新打开后，按照当前日期重新判断。
4. 标题相同的任务允许同时存在，不把标题作为唯一标识。
5. 打开已经删除或不存在的任务时，提示任务不存在，并提供返回入口。
6. 网络异常或保存失败时，不得将未保存的数据展示为已经成功保存。
7. 浏览器刷新后可以重新读取已保存任务；第一版不要求保留未保存的表单内容。
8. 不提供离线编辑，服务不可用时应提示连接失败并允许重试。

## 七 非功能要求

- 页面优先适配桌面浏览器，并保证在 390 像素宽度的小屏上能完成创建、查看和编辑操作。
- 标题、状态、错误提示和主要操作需要清晰可辨，不能只依靠颜色表达任务状态。
- 不将任务描述中的 HTML 或脚本作为可执行内容渲染。
- 用户界面显示中文，日期和时间格式保持一致。
- 保存和查询出现错误时，向用户显示可理解的提示，不展示数据库错误或服务器文件路径。
- 第一版计划承载不超过 2,000 条任务；性能验收设备、测量方式和响应时间阈值需要在开发前确认。

## 八 基础验收场景

1. 创建标题为“整理首版功能清单”的任务，未修改默认值时，状态为待处理、优先级为中。
2. 标题只包含空格时，无法保存，并显示标题校验提示。
3. 将任务分配给成员甲后，按成员甲筛选能够找到该任务；按成员乙筛选时不出现。
4. 将任务从待处理改为进行中后，看板列和状态统计同步更新。
5. 为未完成任务填写昨天的截止日期后，任务显示逾期；改为已完成后，逾期标记消失。
6. 同时设置负责人、状态和优先级筛选后，仅显示同时满足全部条件的任务。
7. 修改任务描述并保存，刷新网页后仍能看到修改后的描述。
8. 重启服务后，已经保存的任务与其状态仍然存在。
9. 取消删除确认时任务不变；确认删除后任务从列表、看板和统计中移除。
10. 搜索无匹配内容时显示空状态，清空筛选后恢复原有任务。
11. 更新请求失败时提示错误，不把状态或字段修改显示为已经保存成功。
12. 在小屏上可以完成新建和编辑，主要操作按钮不被遮挡。

## 九 待确认事项

- 后续是否需要多人登录、同时编辑和角色权限？这些能力是否可能改变当前数据归属设计？
- “一个工作空间最多 2,000 条任务”是否包含已完成任务，是否需要归档机制？
- 列表是否需要分页，看板一次展示多少任务，以及搜索时机，尚未确定。
- 后续是否需要任务数据导出、删除恢复或操作历史？第一版暂不包含。
- 同一任务在两个浏览器窗口被修改时，是接受最后一次保存覆盖，还是要求提示冲突？规则尚未确定。
- 性能测试环境、响应时间目标和首版交付时间，需要业务负责人进一步确认。
